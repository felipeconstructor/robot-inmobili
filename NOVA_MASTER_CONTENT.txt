1. Mensaje entra por /api/chat, /webhook/whatsapp o /webhook/meta

   - Carga propiedades disponibles de Supabase
   - Carga galería de fotos por propiedad
   - Arma prompt dinámico (SISTEMA_BASE + propiedades)
   - Agrega mensaje al historial en memoria (máx 20)
   - Llama Claude API claude-haiku-4-5-20251001 (max 500 tokens)

3. procesarRespuesta(texto, sesionId, canal)
   - Extrae IMAGEN_URL|url → separa imagen del texto
   - Si AGENDAR_VISITA|nombre|tel|prop|fecha|hora:
       → guardarLead() en Supabase (estado: visita)
       → agendarVisita() en Google Calendar
   - Si LEAD_DATOS|nombre|tel|propiedad:
       → guardarLead() en Supabase (estado: nuevo)
   - AGENDAR_VISITA tiene prioridad sobre LEAD_DATOS

4. Respuesta enviada al canal correspondiente

Señales estructuradas:
  AGENDAR_VISITA|nombre|telefono|propiedad|fecha|hora
  LEAD_DATOS|nombre|telefono|propiedad_consultada
  IMAGEN_URL|https://url-de-imagen.jpg

ERRORES CONOCIDOS Y SOLUCIONES
================================================================================

Error: admin panel muestra "Cargando propiedades..." infinito
  Causa 1: URL muerta (alluring-flow-production-16db ya no existe)
  Solución: usar robot-inmobiliario-production.up.railway.app

  Causa 2: Railway Broker tenía código viejo (repo broker-inmobiliario separado)
  Solución: conectar Railway Broker al repo robot-inmobiliario, branch main

  Causa 3: Docker layer cache de Railway usa imagen vieja
  Solución: modificar Dockerfile (COPY . . antes de npm ci) para forzar rebuild

Error: bucket Storage "propiedades" no encontrado (al subir fotos)
  Causa: bucket eliminado o no creado
  Solución: Storage → New bucket → nombre: propiedades, público → agregar 3 policies:
    - allow_upload:  INSERT, anon, bucket_id = 'propiedades'
    - allow_delete:  DELETE, anon, bucket_id = 'propiedades'
    - allow_select:  SELECT, anon, bucket_id = 'propiedades'

Error: columna descripcion no encontrada en Broker
  Causa: tabla creada con "descripcion" sin acento vs "descripción" del código
  Solución SQL: ALTER TABLE propiedades RENAME COLUMN descripcion TO "descripción";

Error: "Object with ID 'me' does not exist" en Messenger/Instagram
  Causa: META_PAGE_TOKEN vencido o es User Token en vez de Page Token
  Solución: developers.facebook.com → Graph API Explorer → Page Token permanente
    Permisos: pages_messaging, pages_read_engagement, instagram_manage_messages

Error: Railway no despliega (Railpack secrets)
  Solución: Dockerfile en la raíz del repo — Railway usa Docker builder

─── VARIABLES QUE DIFERENCIAN CADA CLIENTE ─────────────────────────────────────

  SITE_NAME        → nombre que aparece en login, admin y CRM del cliente
  SUPABASE_URL     → base de datos exclusiva del cliente
  SUPABASE_KEY     → clave de acceso a esa base de datos
  ADMIN_PASSWORD   → contraseña del panel del cliente
  NOTIFY_PHONE     → WhatsApp del dueño donde llegan alertas de leads
  META_VERIFY_TOKEN → token para webhook Meta del cliente (si tiene FB/Instagram)
  META_PAGE_TOKEN  → token de página Meta del cliente

─── CAMBIO A TODOS LOS CLIENTES A LA VEZ ───────────────────────────────────────

  Editar código localmente → git push → Railway redesplíega todos los proyectos
  conectados al repo automáticamente.

  Ejemplo: mejorar diseño del CRM → aplica a Nova/Prolig y Broker simultáneamente.

─── CAMBIO SOLO A UN CLIENTE ESPECÍFICO ─────────────────────────────────────────

  Opción A — sin tocar código (siempre preferida):
    Agregar/editar variable de entorno en Railway del cliente específico.
    Ejemplo: cambiar nombre → cambiar SITE_NAME en ese proyecto Railway.
    Ejemplo: cambiar prompt → agregar variable PROMPT_EXTRA y leerla en server.js.

  Opción B — rama git por cliente (solo si las diferencias son muy grandes):
    Crear rama → conectar ese Railway a esa rama.
    RIESGO: las ramas se desincronizarán con main. Usar con cuidado.

─── QUÉ CONTROLA SITE_NAME ─────────────────────────────────────────────────────

  login.html  → título y footer (ej: "Broker Inmobiliario — Sistema Nova")
  admin.html  → encabezado (ej: "Broker Inmobiliario — Propiedades")
  crm.html    → encabezado (ej: "Broker Inmobiliario — CRM")

  Si no se define SITE_NAME, el servidor detecta por el host:
    host contiene "broker" → "Broker Inmobiliario"
    host contiene "ligua"  → "Corredora La Ligua"
    cualquier otro         → "Nova — Prolig Propiedades"

─── AGREGAR VARIABLES EN RAILWAY (MÉTODO CORRECTO) ─────────────────────────────

  Railway → proyecto → click en el cuadro del SERVICIO → pestaña Variables → Raw Editor
  NO usar Project Settings → Variables (son shared variables que pueden conflictuar)
